Download abgleichen

Vergleiche den SHA-256-Wert der ausgewählten Datei vor der Installation mit der Prüfsummenliste. Ein gleicher Wert bestätigt, dass die Bytes der Referenz entsprechen. Für einen Herkunftsnachweis brauchst du eine unabhängig bestätigte Referenz.

Unter Linux mit dem heruntergeladenen DEB im aktuellen Verzeichnis

sha256sum ./authzledger-verifier_1.5.0-preview1_all.deb

Unter Windows in PowerShell

(Get-FileHash -Algorithm SHA256 .\AuthzLedger-Windows-x64-SelfContained.zip).Hash

Empfängerprüfer einrichten

Debian / Ubuntu

Öffne ein Terminal im Download-Verzeichnis. Mit diesen Befehlen kannst du die Paketmetadaten ansehen und die Vorschau ohne Systeminstallation entpacken. Python ab 3.10 und OpenSSL ab 3.0 müssen bereits installiert sein.

dpkg-deb --info ./authzledger-verifier_1.5.0-preview1_all.deb
dpkg-deb -x ./authzledger-verifier_1.5.0-preview1_all.deb ./pruefer
./pruefer/usr/bin/authzledger-verify --help

Für eine Systeminstallation nutze sudo apt install ./authzledger-verifier_1.5.0-preview1_all.deb. Danach steht authzledger-verify als Befehl bereit. Mit sudo apt remove authzledger-verifier lässt sich das Paket entfernen. Die Installation und Entfernung sowie vier Prüffälle liefen auf Debian 13 und Ubuntu 24.04 erfolgreich.

Windows x64 · Eigenständige EXE

Vergleiche den ZIP-Hash mit der Prüfsummenliste und entpacke das Archiv in einen eigenen Ordner. Python und die Kryptobibliothek sind im Programm enthalten. Es läuft ohne Systeminstallation und benötigt keinen externen OpenSSL-Befehl. Für die Nutzung ist keine Administratorberechtigung erforderlich.

.\AuthzLedgerVerify-1.5.0-win.1-x64.exe --version
.\AuthzLedgerVerify-1.5.0-win.1-x64.exe .\proof --public-key .\vertrauen\mandat.pem
$LASTEXITCODE

Das Archiv enthält SHA256SUMS, windows-native-checks.json und die Lizenzen der mitgelieferten Komponenten. Die EXE trägt keine Authenticode-Signatur. Auf Windows Server 2022 x64 wurden fünf Fälle gegen den Originalprüfer abgeglichen. Windows-Prüflauf

Windows · Optionale Installer-Vorschau

Entpacke das ZIP in einen eigenen Ordner. Es enthält den portablen Prüfer und einen optionalen Installer für das aktuelle Windows-Benutzerkonto. Beide EXE-Dateien sind ohne Authenticode-Signatur. Verwende die tatsächlichen absoluten Pfade deiner vertrauenswürdigen Python- und OpenSSL-Installation. Das Beispiel verwendet Python 3.13 und OpenSSL aus Git für Windows.

$env:AUTHZLEDGER_PYTHON = (& py -3.13 -c "import sys; print(sys.executable)").Trim()
$env:AUTHZLEDGER_OPENSSL = "$env:ProgramFiles\Git\usr\bin\openssl.exe"
Test-Path -LiteralPath $env:AUTHZLEDGER_OPENSSL
.\AuthzLedgerVerify-x64.exe --help

Die Pfadprüfung muss True ergeben. Der historische Windows-Test umfasst das Demo-C-Paket. Für Netzlaufwerke, NTFS-Junctions und mehrfach verschachtelte Übergaben liegt keine allgemeine Freigabe vor. Die zugehörigen Rechtehinweise stehen im ZIP.

Arch Linux

Für das fertig gebaute Paket sind Python ab 3.10 und OpenSSL ab 3.0 erforderlich. Nach dem Hashvergleich installieren, prüfen und später bei Bedarf entfernen

sudo pacman -U ./authzledger-verifier-1.5.0pre1-1-any.pkg.tar.zst
authzledger-verify --help

Zum eigenen Bau sind die Arch-Pakete base-devel, python (ab 3.10) und openssl (ab 3.0) erforderlich. Baue als normaler Benutzer. Die vier lokalen Quelldateien werden gegen festgelegte Hashes geprüft.

tar -xzf AuthzLedger-Arch-Pruefer-PKGBUILD.tar.gz
cd arch-recipient
makepkg --verifysource
makepkg --cleanbuild
makepkg --packagelist

Installiere die von makepkg --packagelist genannte Datei mittels sudo pacman -U ./DATEINAME. Prüfe mit authzledger-verify --help. Entfernen mit sudo pacman -R authzledger-verifier. Das Archiv mit den Quellen ist separat verfügbar. Im nativen Arch-Lauf wurden die Quellen abgeglichen, das Paket gebaut, installiert, mit dem historischen v1.5.0-Demobeleg geprüft und wieder entfernt.

Wheel oder Python-Quelle unter Linux

Erforderlich sind Python ab 3.10 und ein vertrauenswürdiges openssl ab 3.0 im Suchpfad. Für das Wheel werden zusätzlich venv und pip benötigt. Die Installation verwendet die heruntergeladene Datei und benötigt keine Verbindung zu einem Paketindex.

python3 -m venv .venv
.venv/bin/python -m pip install --no-index --no-deps ./authzledger_recipient_verifier-1.5.0.post1-py3-none-any.whl
.venv/bin/authzledger-verify --help

Um das Skript direkt aus der Quelle auszuführen

tar -xzf authzledger_recipient_verifier-1.5.0.post1.tar.gz
cd authzledger_recipient_verifier-1.5.0.post1
python3 -I -B ./authzledger_recipient_verifier.py --help
Docker-Image laden oder aus der Quelle bauen

Lade auf einem Rechner mit Docker-Unterstützung für linux/amd64 den geprüften Export und gleiche dessen SHA-256 ab. Das importierte Image trägt den Tag authzledger-recipient-verifier:1.5.0.post1.

docker load --input ./authzledger-recipient-verifier-1.5.0.post1-linux-amd64.docker.tar.gz
docker image inspect --format '{{.Id}}' authzledger-recipient-verifier:1.5.0.post1

Erwartete Image-ID sha256:810a7b15c7af01ea6fdca083053e9321633467b56db74643e25b8206d7dab4d0.

Im entpackten Python-Quellarchiv liegt das zweistufige Dockerfile. Der Bau benötigt Zugriff auf das Basis-Image und die offiziellen Debian-Pakete. Ein Neubau kann durch aktualisierte Basis-Images oder Systempakete eine andere Image-ID haben.

docker build -t authzledger-recipient-verifier:1.5.0.post1 .
docker run --rm --network none authzledger-recipient-verifier:1.5.0.post1 --help

Für eine Übergabe mit dem Verzeichnis proof und dem separat bestätigten Schlüssel vertrauen/mandat.pem im aktuellen Verzeichnis

docker run --rm --network none --read-only --tmpfs /tmp:rw,nosuid,nodev,noexec \
  --mount type=bind,src="$PWD/proof",dst=/input/proof,readonly \
  --mount type=bind,src="$PWD/vertrauen/mandat.pem",dst=/trust/mandat.pem,readonly \
  authzledger-recipient-verifier:1.5.0.post1 /input/proof --public-key /trust/mandat.pem

Übergabe prüfen

  1. Speichere das entpackte Evidence-Bundle in einem ruhenden, nur lesbaren Verzeichnis. Im Beispiel heisst es proof.
  2. Beschaffe den erwarteten öffentlichen Ed25519-Schlüssel über einen unabhängig bestätigten Kanal. Speichere ihn ausserhalb des Bundles, hier unter vertrauen/mandat.pem.
  3. Starte den Prüfer und ersetze die Beispielpfade durch die tatsächlichen Pfade.
authzledger-verify ./proof --public-key ./vertrauen/mandat.pem

Für die entpackte Debian-Vorschau verwende ./pruefer/usr/bin/authzledger-verify, für das Wheel .venv/bin/authzledger-verify und für das eigenständige Windows-Paket .\AuthzLedgerVerify-1.5.0-win.1-x64.exe.

Exitcode 0 bestätigt Signatur, Inventar, Hashes und Berichtsanker. Bei einer Fehlermeldung bleibt die Übergabe ungeprüft. Ob ein Befund fachlich zutrifft und tatsächlich erneut getestet wurde, ergibt sich aus den zugehörigen Controls und Ausführungsbelegen.
