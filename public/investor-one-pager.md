# AuthzLedger

**Authorization Intelligence, built on evidence**
Investor brief · Switzerland · 25 November 2026

A pentest lead signing off a client engagement needs to know which access decision failed, which control supports that conclusion and which cases were retested. AuthzLedger links those records in a local proof workbench. A reviewer can verify the signed handover using an independently confirmed public key.

## Buyer and purchase trigger

The first buyer is a Swiss security consultancy lead or AppSec manager with a scheduled client handover, a remediation deadline and a named reviewer. A 30-day pilot takes one authorised engagement from intake to acceptance. The team compares review minutes and follow-up questions for the same case set against its previous process.

## What can be verified today

- **Provenance.** Import existing Burp, ZAP, HAR, OpenAPI, Nmap XML or Nuclei JSONL exports. Confirmed findings require supporting evidence and valid control observations.
- **Retest coverage.** A retest references its baseline. Cases without a completed retest remain visible as `not_retested`.
- **Delivery.** Install locally or on a team server. Five roles govern access. The recipient can check the Ed25519 signature on the handover package independently.
